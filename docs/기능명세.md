# 도란도란 기능 명세

이 문서는 **지금 코드에 실제로 구현된 것**을 적습니다. 계획이나 구상은 여기 쓰지 않습니다.
화면 문구·레이아웃의 원본은 Figma 와이어프레임이고, 이 문서는 그 화면들이 어떻게 이어지고
어떤 규칙으로 동작하는지를 설명합니다.

- 마지막 갱신: 2026-08-24
- 코드 기준: `main` 브랜치
- 실행·배포 방법은 [`../README.md`](../README.md)

---

## 0. 한 줄 요약

> 어르신이 **말로** 오늘치 동네 모임을 만들고, 이웃이 한 번 눌러 참여한다.

설계 전체가 이 문장에서 나옵니다. 그래서:

- **타자를 요구하지 않습니다.** 모든 입력 화면에 목소리 경로가 있고, 손으로 쓰기는 대안입니다.
- **오늘만 다룹니다.** 날짜 개념이 없습니다. 시간 필드는 "오후 3시"처럼 시각만 담고, 화면이
  앞에 "오늘"을 고정으로 붙입니다. 그래서 파서는 "내일" 같은 날짜 단어를 일부러 버립니다.
- **한두 시간짜리입니다.** 소요 시간 선택지가 30분 / 1시간 / 2시간 / 2시간 이상뿐입니다.
- **되돌릴 수 있습니다.** 만든 동행은 지우지 않고 `cancelled` 로 표시만 바꿉니다.

### Participant
`meetupId` + `userId` 조합에 유니크 제약. 동행을 만들면 **작성자가 자동으로 참여자 1명**으로 들어갑니다.

> **시간이 문자열인 이유**: 와이어프레임 단계라 "오늘 오후 3시 ~ 5시"를 사람이 읽는 그대로
> 보여주는 게 우선이었습니다. 정렬·만료 처리 같은 게 필요해지면 `DateTime` 으로 옮겨야 합니다.
> 지금은 `status` 를 손으로 바꾸는 것 말고는 만료 처리가 없습니다.

## 2. 화면과 흐름

### 2.1 진입

```
/  →  /splash  →  /location-permission  →  (허용/거부)  →  /signup  →  /welcome  →  /home
```

- `middleware.ts` 가 **첫 진입 게이트**입니다. 어떤 주소로 들어와도 이 브라우저 세션에서
  `/splash` 를 아직 안 거쳤으면 `/splash` 로 보냅니다. `/splash` 방문 시 `dn_entered` 세션
  쿠키를 심습니다. 브라우저를 새로 열면 앱을 다시 켠 것처럼 스플래시부터 시작합니다.
- API 경로와 정적 파일은 이 게이트 대상이 아닙니다.
- `/location-permission` 은 들어오자마자 **위치 이용 동의 팝업**을 띄웁니다. 무엇에 쓰는지
  (가까운 동행 찾기 · 말한 장소를 5km 안에서 찾아 지도 표시 · 길찾기)와, **동의하지 않으면
  무엇이 안 되는지**를 같은 상자 안에 적고 `동의함` / `동의하지 않음` 을 받습니다.
  동의하지 않아도 앱은 계속 쓸 수 있고, 위치가 필요한 기능만 못 씁니다.
- 동의 시 `POST /api/user/location` 으로 좌표를 저장합니다. 세션이 없으면 조용히 넘어갑니다
  (실패로 막지 않습니다).
- 알림 권한은 `/notification-permission?next=...` 로 다음 목적지를 받습니다.
  이 값은 **`safeInternalPath()` 로 검증**한 뒤에만 씁니다.

### 2.2 동행 게시판 `/home`

말풍선 카드가 세로로 쌓인 피드입니다. 각 카드는 `/meetup/[id]` 로 이어집니다.
**현재 카드는 와이어프레임 고정값입니다** — DB에서 목록을 읽어오지 않습니다.

### 2.3 동행 만들기

두 갈래가 같은 초안(`lib/draft.ts`, `sessionStorage`)을 채웁니다.

#### ① 한 화면에서 말로 — `/create/listening`

음성 도우미와 대화하며 세 칸을 채웁니다. 자세한 동작은 [4. 음성 파이프라인](#4-음성-파이프라인).

**장소를 말하면 지도에 핀이 찍힙니다.** 말한 장소 이름을 `POST /api/places/search` 로
**지금 계신 곳 반경 5km 안에서만** 찾아, 장소 칸 아래에 지도·이름·주소·거리를 보여주고
"여기가 맞나요?"를 묻습니다. 틀리면 `고치기` 로 바로잡습니다. 찾은 좌표는 초안에 실려
상세 화면의 지도와 길찾기에 쓰입니다. 못 찾거나 위치를 모르면 지도 없이 그대로 올릴 수 있습니다.

```
들어오자마자 인사 + 첫 질문을 소리로 읽어줍니다
  ↓
"언제 만나고 싶으세요?" → "어디서 만나고 싶으세요?" → "무엇을 하고 싶으세요?"
  ↓
세 칸이 다 차면 [올리기] 활성화 → /create/duration 으로
```

- **질문 순서는 시간 → 장소 → 활동으로 고정**입니다. 앞 항목이 차기 전에는 다음을 묻지 않습니다.
- 순서와 다르게 말해도 기록은 됩니다. 다만 다음 질문은 다시 순서상 첫 번째 빈 항목으로 돌아갑니다.
- 각 칸에 `고치기` 버튼이 있어 손으로 바로잡을 수 있습니다.
- `글자로 입력하셔도 돼요` 입력칸이 항상 있습니다.
- `다시 말할래요` 는 세 칸을 비우고 세션을 새로 엽니다.

#### ② 단계별로 — `/create/activity` 부터

| 단계 | 경로 | 화면 | 선택지 |
|:--:|---|---|---|
| 1 | `/create/activity` | 뭐 하실래요? | 산책 · 등산 · 바둑 · 맛집탐방 · 장보기 · 커피 · 병원 |
| 2 | `/create/time` | 몇 시에 만날까요? | **지금 시각 기준 8개** — 아래 참조 |
| 3 | `/create/duration` | 얼마나 걸릴까요? | 30분 · 1시간 · 2시간 · 2시간 이상 |
| 4 | `/create/place` | 어디서 만날까요? | **지도 + 장소 검색** — 아래 참조 |
| 5 | `/create/people` | 몇 분이 함께할까요? | 2 · 3 · 4 · 5명 |
| 6 | `/create/message` | 하실 말씀 있으세요? | 목소리 또는 손으로 · 건너뛰기 가능 |
| — | `/create/review` | 이대로 올릴까요? | 확인 |
| — | `/create/posted` | 올렸어요 | **여기서 실제 저장** |

- **2단계 선택지는 고정 목록이 아닙니다.** 고정 목록은 아침에 열면 이미 지난 시각을 고르게 되고
  저녁에 열면 쓸모가 없습니다. 그래서 **지금부터 1시간 이상 떨어진 첫 정각**부터 30분 간격으로
  8개(정각 4개 + 30분 4개)를 만듭니다. 계산은 서버가 **한국 시각**으로 합니다
  (`seoulNow()` — 서버는 UTC로 돌기 때문). 목록에 없으면 아래 입력칸에 직접 쓰거나 말합니다.

  예) 8시 55분에 열면 → 오전 10시 · 10시 30분 · 11시 · 11시 30분 · 오후 12시 · 12시 30분 · 1시 · 1시 30분

  > 밤늦게 열면 새벽 시각이 그대로 나옵니다(23시에 열면 오전 1시~2시 30분). 어르신 대상 앱에는
  > 어울리지 않지만, 앱에 날짜 개념이 없어 "내일 아침"으로 넘길 수단이 아직 없습니다.
- 3단계에서 **끝나는 시각을 계산해 보여줍니다.** `lib/koreanTime.ts` 가 `오후 3시 + 120분 → 오후 5시`
  처럼 정오·자정 경계를 넘겨가며 계산합니다. `2시간 이상`을 고르면 끝 시각을 정하지 않습니다.
- **4단계는 고정 카드가 아니라 지도 + 검색입니다.** 미리 박아둔 세 곳("송정마을 어귀" 등)은
  어느 동네에서 열든 똑같이 나와 쓸 수가 없었습니다. 지금은 지도에 계신 곳을 띄우고,
  아래 칸에 장소를 쓰거나 말하면 `POST /api/places/search` 로 **반경 5km 안에서** 찾아
  지도에 핀을 찍고 이름·주소·거리를 보여줍니다. `여기서 만날게요` 로 확정하면 좌표까지
  초안에 담겨 상세 화면의 지도·길찾기로 이어집니다.
  - 못 찾으면 `적은 그대로 쓸게요` 로 적은 글자를 그대로 씁니다(막다른 길을 만들지 않습니다).
  - 위치를 모르면 지도 없이 적은 그대로 씁니다. 이때는 버튼 문구도 `이걸로 할게요` 로 바뀝니다.
  - 이 화면만 `목록에 없으면` 머리말이 없습니다 — 고를 목록이 없기 때문입니다.
    다른 화면은 그대로 둡니다.
- 3단계 뒤에 **이미 장소를 알면 4단계를 건너뜁니다** (①번 경로로 들어와 장소를 이미 말한 경우).
- 6단계는 선택입니다. `건너뛸래요` 를 누르면 앞서 넣었던 한마디까지 지우고 넘어갑니다.

> **저장 시점 주의**: `/create/review` 까지는 전부 브라우저 안(`sessionStorage`)에만 있습니다.
> `/create/posted` 에 도착해야 `POST /api/meetups` 가 나갑니다. 중간에 창을 닫으면 아무것도
> 남지 않습니다. 새로고침도 세션 저장소라 같은 탭에서는 살아있지만 탭을 닫으면 사라집니다.

### 2.4 동행 자세히 보기 `/meetup/[id]`

Figma `오늘마실_동행자세히보기 1` 기준.

```
오후 3시 30분
도란마트 장보러 가요
│ "천천히 둘러볼게요.
│  무거운 건 안 사요."      ← 06_하실 말씀. 초록 세로선(#3D6B5A) + 따옴표, 문장마다 줄바꿈
───────────────────────
걸리는 시간 / 모임인원 / 거리 / 만나는 곳
[지도]
[참여하기]  [다른 동행 보기]
```

- **제목 · 시각 · 한마디 · 만나는 곳 · 지도는 DB에서 읽습니다.** 나머지 항목(걸리는 시간·인원·거리)은
  아직 와이어프레임 고정값입니다.
- 한마디가 없으면 인용 칸 자체가 나오지 않습니다.
- **`길찾기 >` 는 지도 앱으로 넘깁니다.** 폰에서 누르면 구글 지도 앱이 열리고 출발지는 지금
  계신 곳이 됩니다. **걷기 안내가 기본**입니다 — 이 앱은 걸어서 갈 거리의 동행만 다룹니다.
  좌표가 있으면 좌표로(정확), 없으면 장소 이름으로 엽니다.
  같은 링크가 동행 만들기의 장소 확인 자리(`/create/place`, `/create/listening`)에도 있어
  **고르기 전에** 얼마나 걸리는지 볼 수 있습니다.
- **좌표가 없는 동행은 지도 자리를 비웁니다.** 가짜 위치를 보여주지 않습니다.
- `참여하기` → `/meetup/[id]/complete` (`참여 완료!`). 현재 참여 기록을 DB에 쓰지는 않습니다.

### 2.5 내 동행 `/my-meetups`

- `/my-meetups/created` — 내가(=`uid` 쿠키) 만든 동행을 최신순으로. 올린 직후 바로 나타납니다.
  진행중과 취소됨이 나뉘어 보이고, 취소된 것은 취소한 날짜가 붙습니다.
- **모임 카드를 누르면 동행 자세히 보기로 갑니다** (참여한 동행·만든 동행 양쪽). 카드 안의
  `취소하기` 버튼은 링크 밖에 두어, 카드를 눌러도 취소가 눌리지 않습니다.
- `/my-meetups/cancel` → `/my-meetups/cancel/complete` — 참여 취소.
  **취소 사유는 상대에게 보이지 않습니다.**
- `/my-meetups/expired` — 지난 동행.

## 3. API

### `POST /api/meetups` — 동행 등록
요청: `{ activity, startTime, locationName, lat?, lng?, maxPeople?, message? }`
모든 항목에 기본값이 있어 빈 요청도 통과합니다(와이어프레임 편의).
`uid` 쿠키가 없거나 그 사용자가 없으면 **첫 번째 사용자 또는 새 데모 사용자**를 작성자로 씁니다.
저장 후 작성자를 참여자로 자동 추가합니다.

### `POST /api/meetups/[id]/cancel` — 취소
`uid` 없으면 401, 없는 동행이면 404, **작성자 본인이 아니면 거부**.
지우지 않고 `status = "cancelled"` + `cancelledAt` 을 씁니다.

### `POST /api/parse-meetup` — 발화에서 세 칸 뽑기
요청: `{ transcript, time, location, activity }` — 뒤 셋은 **지금 화면에 있는 값**입니다.
응답: `{ time, location, activity, missingField, followUpQuestion }`

규칙:
- 이번 발화에 없는 필드는 **기존 값을 유지**합니다.
- **정정을 알아듣습니다**: `3시 말고 4시`, `공원으로 바꿔줘`, `아니 5시야`, `한 시간 미뤄`(+1시간),
  `30분 당겨`(−30분). 필드 이름을 말하지 않아도 값의 종류(시각/장소명/활동)로 판단합니다.
- **비우기**: `장소는 다시 정할래` → 그 필드를 빈 문자열로 반환 → 화면이 비우고 다시 묻습니다.
  "원래 몰랐음(null)"과 구분하기 위한 장치입니다.
- **길게 말하면 요약합니다**: 장소·활동은 화면 칸에 들어갈 짧은 명사구(대략 12자 이내)로 줄입니다.
  조사·수식어·사연은 버립니다.
- **시각은 항상 `오전`/`오후` + 아라비아 숫자로 정규화**합니다. `네 시` → `오후 4시`.
  이걸 안 지키면 3단계의 끝시각 계산이 조용히 실패합니다.
- 날짜 단어(`오늘`/`내일`)는 뺍니다 — 화면이 "오늘"을 고정으로 붙이기 때문입니다.
- `OPENAI_API_KEY` 가 없거나 호출이 실패하면 **입력을 그대로 되돌려주고 첫 빈 필드를 묻습니다**
  (결정적 폴백, LLM 미사용).

### `POST /api/summarize-message` — 한마디 요약
요청: `{ transcript }` → 응답: `{ message }`

- **최대 2문장, 문장당 20자 이내.** 문장마다 줄바꿈해서 돌려줍니다.
- 어르신이 직접 말하는 존댓말 평서문을 유지합니다. 3인칭 설명으로 바꾸지 않습니다.
- 없는 내용을 지어내지 않습니다. 요약할 알맹이가 없으면 빈 문자열입니다.
- 모델이 길게 뱉어도 **서버에서 한 번 더 자릅니다.**
- 키가 없거나 실패하면 들은 말이라도 잘라서 돌려줍니다(빈 화면 방지).

예: `제가 무릎이 좀 안 좋아서 빨리는 못 걸어요. 그냥 천천히 둘러보기만 할 거고 무거운 건 살 생각이 없어요`
→ `천천히 둘러볼게요.` / `무거운 건 안 사요.`

### `POST /api/places/search` — 말한 장소 → 좌표
요청: `{ query, lat, lng }` (뒤 둘은 지금 계신 곳) → 응답: `{ place, others, source }`
`place` = `{ name, address, lat, lng, distanceM }` 또는 `null`.

- **반경 5km를 넘는 결과는 절대 돌려주지 않습니다.** 걸어서 갈 수 있는 곳만 다루는 앱이라
  같은 이름의 먼 동네 가게가 잡히면 안 됩니다.
- 1순위 **Places API (New)** `searchText` — 가게·경로당·시장 같은 시설 이름을 제대로 찾습니다.
  `locationRestriction` 은 **원(circle)을 받지 않고 사각형만** 받습니다(원으로 보내면
  `400 INVALID_ARGUMENT`). 그래서 5km를 감싸는 사각형으로 좁힙니다.
- 2순위 **Geocoding** — Places 가 꺼져 있으면 여기로 폴백합니다. 주소·동네 이름 위주라
  시설 이름은 잘 못 찾습니다. 마찬가지로 사각형으로 좁힙니다.
- **5km 보장은 두 경로 모두 응답을 받은 뒤 실제 거리(Haversine)로 자르는 데서 나옵니다.**
  사각형은 원의 외접이라 모서리가 반경을 넘칩니다. 이 필터가 그걸 잘라냅니다.
- Places 는 검색엔진이라 근처에 없는 이름을 물으면 **비슷한 다른 곳**을 줍니다
  (예: "도란마트" → "이마트 왕십리점"). 그래서 화면이 찾은 이름·주소·거리를 보여주고
  어르신이 눈으로 확인한 뒤 `여기서 만날게요` 를 누르게 합니다.
- 위치를 모르면 `reason: "no-origin"`. **`Number(null)` 이 0이 되어 적도(0,0)로 검색되는 일이
  없도록** 실제 숫자만 받습니다.

> **Places API (New) 활성화 필요.** 키의 "API 제한사항" 목록에 넣는 것만으로는 안 됩니다 —
> `API 및 서비스 > 라이브러리` 에서 서비스를 켜야 하고, 안 켜져 있으면 `403 SERVICE_DISABLED`
> 로 Geocoding 폴백으로 떨어집니다. (2026-08-24 활성화 완료)

### `POST /api/realtime/session` — 음성 세션 키
OpenAI Realtime 용 **단수명 클라이언트 시크릿**을 발급합니다.
브라우저는 이 값으로만 WebRTC 연결하고, **본 API 키는 서버 밖으로 나가지 않습니다.**
모델 `gpt-realtime`, 전사 `gpt-4o-mini-transcribe`(한국어), 서버 VAD 침묵 1.6초.

### `POST /api/transcribe` — 녹음 → 글자
`whisper-1`, 한국어 고정.
**확장자를 실제 MIME 타입에서 유도합니다** — iOS 사파리는 `audio/mp4` 로 녹음하는데
무조건 `.webm` 으로 이름 붙이면 Whisper 가 포맷 불일치로 거부합니다.

### `POST /api/tts` — 글자 → 소리
`tts-1`, 목소리 `alloy`, mp3.

### `POST /api/auth/demo` — 데모 로그인
"형용사 + 동물" 별명으로 사용자를 만들고 `uid` 쿠키(httpOnly, 1년)를 심습니다.

### `POST /api/user/location` — 위치 저장
세션이 없거나 좌표가 이상하면 **에러 대신 조용히 통과**합니다. 위치는 부가 기능이라
실패로 화면을 막지 않습니다.

## 4. 음성 파이프라인

가장 복잡한 부분입니다. `/create/listening` 은 **두 개의 인식 경로를 동시에** 돌립니다.

```
                  ┌─ ① 실시간 에이전트 (WebRTC) ─────────────┐
마이크 한 개  ──┤   말을 듣고 직접 되묻고,                  ├─→  시간/장소/활동
   (공유)        │   set_meetup_fields 도구로 칸을 채움      │      세 칸
                  └────────────────────────────────────────┘
                  ┌─ ② 보조 인식 루프 ──────────────────────┐
                  │   녹음 → Whisper → /api/parse-meetup    │
                  └────────────────────────────────────────┘
```

**왜 두 개인가**: ①의 전사 이벤트가 브라우저까지 안 오는 환경이 있습니다. ②는 그때도
말씀 한 번마다 반드시 칸을 채우기 위한 안전망입니다. iOS 는 두 번째 마이크 캡처가 WebRTC
오디오 세션과 충돌해서 ②를 끕니다.

### 두 경로가 같은 칸을 쓸 때의 규칙

이게 이 화면의 핵심 규칙이고, 여기를 어기면 **"다 채웠는데 계속 묻는"** 증상이 납니다.

1. **파서 응답은 통째로 덮어쓰지 않습니다.** ②의 요청은 보낼 때의 값(스냅샷) 기준으로 계산되는데,
   응답이 오기까지 1~3초 사이에 ①이 채운 값은 그 스냅샷에 없습니다. 그래서
   `applyParse()`(`lib/meetupDialog.ts`)가 **이번 파싱이 실제로 바꾼 필드만** 반영합니다.
2. **필드를 바꾸는 모든 경로는 `commitFields()` 한 곳을 지납니다.** 여기서 ref 를 동기로
   갱신하므로 "다음 질문" 판단이 한 박자 늦은 값을 보지 않습니다.
3. **남은 항목은 서버 응답이 아니라 병합 결과로 다시 계산합니다.**
4. **에이전트가 모르는 화면 변경은 알려줍니다.** ②나 `고치기` 가 칸을 채우면
   `[화면에 기록된 내용] ...` 을 세션에 넣습니다. 이때 **응답을 트리거하지 않습니다**
   (`triggerResponse: false`) — 도우미가 말하는 중에 응답이 겹치면 서버 오류가 납니다.
5. **`set_meetup_fields` 도구는 절대 실패하지 않습니다.** 실패를 돌려주면 에이전트가 재시도를
   반복하다 "계속 문제가 있어서 죄송합니다"류의 사과 루프에 빠집니다. 도구는 항상 성공을
   돌려주고, **결과에 화면의 최종 상태를 함께 담습니다**.

### 긴 발화 처리

어르신은 한 문장 안에서도 쉬었다 말합니다. 말 끝 판정이 짧으면 문장 앞토막만 전달됩니다.

| 지점 | 값 |
|---|---|
| 실시간 세션 서버 VAD 침묵 | 1.6초 |
| 보조 루프 침묵 판정 | 1.8초 |
| 보조 루프 최대 녹음 | 30초 |
| 무발화 타임아웃 | 8초 |

길게 말한 내용은 **잘라내지 않고 요약해서** 칸에 넣습니다(3번 파서 규칙 참조).

### 목소리가 겹치지 않게

- 도우미(①)가 말하는 동안 ②는 귀를 닫습니다. 도우미 목소리가 마이크로 되돌아 들어가는 것을
  막기 위해 마이크에 에코 캔슬을 켭니다.
- ②가 질문을 읽어주기 전에 **3초간 ①에게 양보**합니다. 그 사이 ①이 말하기 시작하면 ②는 침묵합니다.
- 인사말은 화면(TTS)이 담당합니다. 에이전트는 먼저 인사하지 않고 어르신의 첫 응답부터 이어받습니다.

### 브라우저 제약

- **소리 잠금**: 사용자가 화면을 한 번 누르기 전에는 재생이 막힙니다. 마이크 버튼 탭에서
  `unlockAudio()` / `unlockAgentAudio()` 로 해제합니다.
- **마이크**: HTTPS 또는 localhost 에서만 열립니다.
- **진단 표시줄**: 마이크 버튼 아래 작은 회색 글씨에 마지막 3건이 찍힙니다
  (`입력장치: ...`, `마이크 송신 정상(NKB/4초)`, `마이크 송신 0` 등).

## 6. 아직 안 된 것 (알고 있는 공백)

정직하게 적습니다. 이 목록에 있는 것을 "된다"고 말하지 마세요.

- `/home` 게시판이 **DB를 읽지 않습니다.** 카드가 와이어프레임 고정값입니다.
- `/meetup/[id]` 의 걸리는 시간·인원·거리는 **고정값**입니다. 제목·시각·한마디·만나는 곳·지도·길찾기는 실제 값입니다.
- `참여하기` 가 **참여 기록을 남기지 않습니다.** 완료 화면만 보여줍니다.
- **거리 계산이 없습니다.** `걸어서 8분` 과 `· 걸어서 12분` 은 고정 문자열입니다.
  좌표가 생겼으니 실제 계산으로 바꿀 수 있지만 아직 안 했습니다.
- `/my-meetups`(참여한 동행)는 **고정 카드**라 카드 링크가 `/meetup/1~3` 을 가리킵니다.
  참여 기록이 DB에 없어서 실제 id 를 붙일 수 없습니다.
- **만료 처리가 없습니다.** `startTime` 이 문자열이라 시간이 지나도 `status` 가 자동으로 안 바뀝니다.
- **밤에 열면 새벽 시각이 선택지로 나옵니다.** 날짜 개념이 없어 "내일 아침"으로 넘길 수 없습니다.
- **알림이 없습니다.** 권한 화면만 있고 실제 푸시는 보내지 않습니다.
- **실제 로그인이 없습니다.** 데모 로그인만 있습니다(카카오 3초 로그인은 와이어프레임에만 있음).
- `/create/listening` 의 **보조 인식 루프는 중복 질문의 근원**입니다. 실시간 전사 이벤트가
  안정적으로 오는 것이 확인되면 통째로 지우는 것이 맞습니다.

## 7. 회귀 검증에서 지키는 계약

`scripts/check.mjs` — `npm run check`. 아래가 깨지면 사용자에게 바로 보이는 고장입니다.

**유닛 (서버 불필요)**
- 시간 계산: `오후 3시 + 2시간 = 오후 5시`, 정오·자정 경계 뒤집힘, 오전/오후 없으면 `null`
- 만날 시각 선택지: 8개(정각 4 + 30분 4) · `8시 55분 → 오전 10시부터` · 정각에 열면 바로 1시간 뒤부터
  · 자정·정오 경계에서 오전/오후 뒤집힘 · `seoulNow()` 가 한국 시각을 가리킴
- 질문 순서: 빈 상태 → `time`, 시간 차면 → `location`, 다 차면 → `null`
- 필드 병합: 동시 기록 시 상대가 채운 값 보존 · 비우기 반영 · 정정 반영 · 미변경 필드 유지

**계약 (서버 필요, 실제 LLM 호출)**
- 빈 발화 → 결정적 폴백으로 첫 빈 필드를 물음
- 완전한 한 문장 → 세 필드 모두 추출
- `3시 말고 4시로 해줘` → 시간만 4시로, 다른 필드 유지
- `한 시간 미뤄줘` → +1시간 계산
- `그거 말고 뜨개질로 하자` → 필드 이름 없이도 활동 교체
- `장소는 다시 정할래` → 장소 비우고 재질문
- 긴 발화 → 짧게 요약된 활동, 다른 필드는 안 흔들림
- `네 시쯤에 봐요` → `오후 4시` 로 정규화되어 끝시각 계산이 성공
- 하실 말씀: 최대 2문장 · 문장당 20자 이내 · 알맹이 없으면 빈 문자열
- 장소 검색: **돌려주는 모든 결과가 5km 안**(서울/제주 3가지 질의로 확인) · 가까운 순 정렬 ·
  빈 질의는 `no-query` · 위치 없으면 `no-origin`
- 길찾기 링크: 좌표가 있으면 좌표로 · 없으면 이름으로 · 걷기 안내 기본 · 이동수단 지정 가능
- 04_어디서 만날까요에 고정 카드가 없고 `목록에 없으면` 머리말도 없음 · 나머지 화면은 머리말 유지
