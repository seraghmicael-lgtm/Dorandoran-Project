# Dorandoran v3 재작업 지시서 (2026-08-21, Figma 전면 재설계 반영)

Figma에 새 섹션 `와이어프레임_v01`(764:48) + `기타 추가 기능`(764:13)이 추가되며 사실상
전면 재설계됐다. 이 문서가 v2 → v3 전환의 유일한 근거다. **여기 없는 문구·기능·아이콘·색은
절대 지어내지 말 것.** 텍스트는 `docs/figma-wireframe-spec-v3/*.txt`에서 그대로 가져오고,
레이아웃은 `docs/figma-wireframe-spec-v3/screenshots/*.png`를 최대한 그대로 따른다.

## 핵심 변화 (v2 → v3)
- 스플래시 버튼이 "카카오로 시작하기"/"휴대폰 번호로 시작하기"/"그냥 둘러보기" 3개에서
  **"동네 인증하고 시작하기" 1개**로 단순화됨.
- **로그인이 다시 지연 방식으로 회귀함** (사용자 직접 확정, 2026-08-21): 스플래시 → 위치권한 →
  홈까지는 로그인 없이 진행. 로그인("회원가입" 화면, 구 "로그인"/"카톡 3초 로그인")은 "만들기" 등
  실제로 필요한 시점에만 요구된다. v2에서 "로그인은 진입과 동시에"로 정했던 걸 다시 뒤집는 것이니
  헷갈리지 말 것 — 이번이 최신 결정이다.
- "동행 만들기" 플로우가 텍스트 입력 4단계(모임명→소개/시간/인원/장소)에서
  **음성 우선 대화형 플로우**로 전면 교체: 01_말하기 → 02_듣는 중 → 03_이렇게 들었어요 → 05_올렸어요,
  손글씨 입력은 06_손으로 쓰기(폴백)로 별도. 최대인원/예상소요시간 칩·스테퍼 같은 구조화 입력 없음 —
  자연어 문장에서 시간/장소/활동을 추출해 "고치기" 링크로 수정하는 방식.
- 홈 화면(04_홈) 전면 재설계: "오늘, {동네} 마실 어떠세요?" 타이틀, 카드 리스트 사이에
  **"Ad·동네광고" 스폰서 카드** 신규, 하단 탭 3번째가 "동네소식" → **"내정보"**로 교체.
- 모임 상세(상세 확인) 재설계: 게시자 신뢰카드(동행참여N회·참여도)와 추천 리스트가 빠지고
  단순 정보나열(만드신분/걸리는시간/모임인원/거리/만나는곳+길찾기)+지도+참여하기/다른 동행 보기로 축소.
- 신청완료 문구 "신청되었습니다"→"참여 완료!", 참여취소/처리완료 문구도 갱신됨.
- NEW: "07_불발 알림" — 모집 실패(시간경과) 시 안내 + 같은 내용으로 다시 열기 + 비슷한 시간대 추천.
- **`기타 추가 기능`(764:13) 섹션 안의 "내 동행" 화면만 예외적으로 구 3탭(홈/내동행/더보기)을 그대로
  쓰고 있다** — 04_홈의 새 4탭과 다름. Figma 원본이 그렇게 돼 있으므로(직접 대조 확인) 지어내서
  통일하지 말고 각 화면 스펙 그대로 구현할 것.

## 진입 순서 (사용자 직접 확정)
`/splash`("동네 인증하고 시작하기") → `/location-permission`("위치 허용하기") → `/home`.
로그인 없이 바로 홈 진입.

**정정 (사용자 재확정, 2차)**: "만들기" 탭은 로그인 게이트 없이 **곧장 `/create/speak`(01_말하기)로
진입한다.** 회원가입/알림허용은 만들기 탭 경로가 아니다 — 아래 10~12번 라우트는 만들되, 진입
트리거는 스펙에 명시가 없으므로 routes 인덱스로만 접근 가능한 상태로 둔다(추측으로 연결하지 않음).
01_말하기의 "누르고 말하기" → 02_듣는_중 → 03_이렇게_들었어요 → 05_올렸어요 순서는 사용자가
그대로 확인함(변경 없음).

모임 상세→참여하기는 로그인 게이트 없이 바로 신청완료로 진행(Figma에 별도 게이트 화면이 없음 —
디자이너 자신도 리서치 메모에 "모임 상세보기를 누를 시 로그인 필요?"라고 미결 상태로 남겨둔 질문이라
현재 화면 구성 그대로, 지어내지 않음).

## 지켜야 할 기존 원칙 (v1·v2 다회 적대적 리뷰에서 확립됨, 여전히 유효)
- `?from=`/`?next=` 쿼리 기반 back-nav는 반드시 `lib/safePath.ts`의 `safeInternalPath`를 거칠 것
  (오픈 리다이렉트 검증됨, WHATWG URL 파서 기반 — 문자열 접두사 검사로 되돌리지 말 것).
- `WireframeLayout`은 `justify`/`items` prop으로만 정렬 바꿀 것. 이 컴포넌트는 이제 모든 화면에
  하단 탭바를 자동으로 붙인다(usePathname 기반) — 단 `/my-meetups`류는 BottomNavThree를 직접
  써야 하므로, WireframeLayout이 자동으로 붙이는 BottomNavFive와 겹치지 않도록 처리 방법을 agy가
  판단해서 정리할 것(예: WireframeLayout에 `bottomNav="five"|"three"|"none"` prop 추가 등 — 구조는
  agy 재량, 단 두 개가 동시에 뜨는 일은 없어야 한다).
- 스펙에 없는 목적지·문구·아이콘은 절대 만들지 말 것. 애매하면 비활성(회색, cursor-not-allowed span)
  으로 처리하고 지어내지 않는다.
- 순수 와이어프레임 스타일 유지(흰배경/검정·회색 텍스트/얇은 회색 라인/검정 or 테두리 버튼).
